# **1. Поведение алгоритмов по количеству посимвольных сравнений**

Ключевым отличием строковых сортировок является оптимизация работы с префиксами. Эмпирические данные полностью подтверждают теоретические оценки:

### **Стандартные алгоритмы (Standard QuickSort и MergeSort)**

Стандартные сортировки работают за $\Omega(N \log N)$ сравнений самих строк. Однако внутри каждого сравнения может скрываться цикл по символам.

* **Standard QuickSort** демонстрирует худшие показатели (более 480 000 сравнений на массиве из 2900 случайных строк), так как при каждом разбиении он заново сравнивает совпадающие префиксы с опорным элементом.
* **Standard MergeSort** показывает значительно меньшее число сравнений (около 42 000 на N=2900), но всё равно совершает лишнюю работу на глубоких этапах слияния.

### **Специализированные алгоритмы**

* **String MergeSort:** Использование кэширования длин наибольших общих префиксов (LCP) радикально снизило число сравнений. По сравнению со стандартным MergeSort, количество посимвольных проверок упало почти в 2 раза (с 42 652 до 26 905 на N=2900 для Random). При слиянии алгоритм пропускает известные совпадающие символы.
* **Ternary QuickSort:** Тернарное разбиение позволило группировать строки по текущему символу и сдвигаться вправо (`L+1`). Это отсекает повторные проверки префиксов, что делает график сравнений значительно более пологим.
* **MSD Radix Sort:** График сравнений для этого алгоритма **лежит на нуле**. Это объясняется тем, что на этапе распределения используется сортировка подсчетом (Counting Sort), которая опирается на прямую адресацию по коду символа, а не на операторы сравнения элементов.

# **2. Поведение алгоритмов по времени выполнения**

### **Влияние адаптации на скорость**

Адаптированные алгоритмы ожидаемо оказались быстрее стандартных реализаций. На массиве из 2900 случайных элементов:

* Самым медленным оказался **Standard QuickSort** (около 6000 мкс).
* Самым быстрым — **MSD Radix+Quick** (около 1577 мкс).

### **Эффект гибридизации (MSD Radix+Quick)**

Чистый `MSD Radix Sort` крайне эффективен на верхних уровнях, но при сильном дроблении массива (когда размер корзины становится малым) затраты на создание массива частот `count` на 256 элементов становятся неоправданными.
Эксперимент показывает, что модификация **MSD Radix+Quick** (с переключением на `Ternary QuickSort` при длине подмассива < 74) стабильно опережает или идет наравне с чистым Radix Sort по времени, особенно на почти отсортированных (Almost) и случайных (Random) данных. Побочным эффектом является появление небольшого числа посимвольных сравнений (от работы QuickSort на малых отрезках).

# **3. Влияние характера данных**

1. **Random (Случайные):** Служат базовым сценарием. Алгоритмы демонстрируют свое усредненное поведение.
2. **Reversed (Обратно отсортированные):** На этих данных `String MergeSort` показал феноменальное снижение числа сравнений (всего около 10 000 проверок на N=2900 против 26 905 на случайных). Это связано с тем, что на обратных данных соседние элементы часто имеют меньшую длину общих префиксов в начальных фазах слияния, и алгоритм быстрее находит отличия.
3. **Almost (Почти отсортированные):** `MSD Radix+Quick` здесь показал лучшее время (около 1273 мкс на N=2900), так как переключение на быструю сортировку на нижних уровнях мгновенно упорядочивает оставшиеся небольшие аномалии в массиве без лишних рекурсивных спусков.

---

# **4. Содержательные выводы**

1. **Излишние посимвольные сравнения стоит избегать.** Стандартные алгоритмы совершают колоссальное количество лишней работы, сравнивая одинаковые префиксы строк на каждом шаге.
2. **Кэширование LCP работает.** `String MergeSort` сохраняет устойчивость оригинального алгоритма, но избавляется от его главного недостатка, строго контролируя пропуск уже проверенных префиксов.
3. **MSD Radix Sort — абсолютный лидер по минимизации сравнений**, так как обходит саму парадигму сортировок, основанных на сравнениях, используя Counting Sort.
4. **Гибридизация — ключ к максимальной производительности на практике.** Комбинирование MSD Radix Sort (для грубого распределения по префиксам) и Ternary QuickSort (для быстрой сортировки малых остатков) дает наиболее оптимальный результат по времени выполнения.
